# Smash & Stab

Cooperative heist-style game, top-down/isometric camera, 2D animated sprite avatars via Live2D
Cubism. Separate project from Aby — no shared game content, only briefly and mistakenly merged
into Aby's Unity project shell (see `../smashandstab-aby-attempt/README.md`); this is the clean
extraction, with that merge's additions removed.

Original source: `ThetaGameDev/SmashandStab`.

## What's here

Real gameplay: player controller, enemies, weapons/items, procedural map generation
(`Assets/Scripts/MapGen`), Netcode for GameObjects multiplayer, an objective/scoring system, and
Live2D-driven character sprites.

Removed from the Aby-merge snapshot: `Assets/Plugins/Escher/*` (Aby's JS runtime plugin),
`Assets/Editor/Aby/*` (Aby's editor tooling), the root-level `Data/`/`Examples/` Escher demo
scripts and the `GameInitialization.cs` hook that called them, `package.json` (Aby's package
descriptor), and all `.sln`/`.csproj`/`.slnx` files (regenerated by Unity on open — the ones
committed here belonged to the Aby shell and referenced the wrong paths).

## Status

Verified 2026-08-15: headless batchmode import/compile is clean on Unity 6000.3.8f1 (0 `error CS`,
clean exit) both before and after the strip above. Netcode for GameObjects, Live2D Cubism, and the
rest of `Packages/manifest.json` all resolve.

Scene flow, inferred from `ProjectSceneManager.cs` and scene contents: `Scene_Menu` →
`Scene_Lobby` (has the real orchestration: `NetworkManager`, `ProjectSceneManager`,
`NetworkSpawner`, `NetworkObjectiveManager`) → additively loads `Scene_Main` (the actual play
space) once a host starts. `RegShooting`, `DebugMapScene`, and `MergeScene` look like standalone
feature-test scenes, not part of the main flow.

Not yet exercised: nobody has actually pressed Play and hosted/joined a round on this machine.
Static check (tags referenced via `FindGameObjectWithTag` vs. tags present in-scene) came back
clean except one **pre-existing bug, not introduced by this cleanup**: `Main_UI.cs`'s end-round
handler does `GameObject.FindWithTag("MapGenerator")`, but nothing in `Scene_Main` (or anywhere
else) actually carries that tag — it'll return null and throw when a player ends a round. Fix is
probably a one-line tag assignment on the map generator's GameObject in `Scene_Main`, once
someone's in the Editor to confirm which object that should be.

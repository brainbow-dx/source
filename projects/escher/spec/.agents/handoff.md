## Just landed (commit `633a8a5`, pushed to `escher/mario-platform-polish`)

- **Phase 1 (`.output/` sweep)** — fully done and checked off. All 6 docs projects + the template now build mdbook output under `.output/docs` via multi-stage Dockerfiles; verified with real `mdbook build` runs.
- **Phase 2 (real command host API)** — the sentinel-string pattern (`QUIT_SENTINEL`/`CLEAR_SENTINEL`, where a command's *display text* doubled as a signal Rust grepped for) is gone. `ethos-deno` has a new `host_actions` module: one generic op (`op_host_action`) carrying a real `{ type, ...data }` structured message, not a bare string. `commands/quit.js`/`commands/clear.js` call it through a familiar `postMessage(message)` wrapper.
  - **Non-obvious finding worth remembering**: a script can't just call `Deno.core.ops.op_host_action(...)` directly. `deno_runtime`'s own bootstrap (`99_main.js`) deletes every op not on its own hardcoded CLI allowlist from `Deno.core.ops` before any command script runs, and separately replaces the whole `Deno` namespace object outright — so anything hung off the pre-bootstrap `Deno` is lost too. The fix: `host_actions_init.js`, a classic (non-module, eagerly-evaluated) extension script that grabs a direct reference to the op function at extension-init time, before either of those things happen, and hangs it off `globalThis.__ethosHostAction` instead — see the doc comment at the top of `ethos/packages/deno/src/host_actions.rs` for the full reasoning, or `spec/.agents/proposals/anvil-command-host-api.md`.
  - Real test (`host_actions.rs`'s own `#[test]`) drives the actual `run_module_command`/`bootstrap_main_worker` path end to end with a live script and passes.
  - `cargo check` is clean for `ethos-deno`, `ethos` (apps/cli), and `escher-anvil`.
  - **Not yet done**: a real tmux live-verify of `/quit` and `/clear` actually working in a running `escher-anvil` instance. Deferred because a full binary *link* build (not just `cargo check`) got disk down to ~6.4Gi free earlier this session after repeated builds — check `df -h /` before attempting, and consider whether the unit test above is sufficient confidence given the risk, or whether it's worth doing anyway. Also still open: whether `/relay-console` becomes a real discovered command on this same API, or stays a documented Rust-native exception (it manages a long-lived subprocess).
- Also folded into this same commit (already-complete work from earlier in this long session, just not committed yet): the em-dash → plain-prose comment rewrite across escher/ethos/atlas/eden, a `color-eyre` build-dependency regression fix, and an `open-page.js`/`serve-relay-console.ts` path-resolution bug fix in Anvil (`anvil_scripts_dir` now derives the scripts dir from wherever `commands/` was actually found at runtime, instead of assuming a fixed relationship to the cwd).

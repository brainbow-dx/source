## Standing lesson from this round

When verifying "is this dependency actually unused," checking `src/`, a root-level `build.rs`, `examples/`, `tests/`, `benches/` is not enough — a crate's build script can live anywhere via `build = "<path>"` in `Cargo.toml`, and grep-based unused-dependency checks need to resolve that path, not assume the default. This is the second class of false-positive found in dependency cleanup this session (the first: `dep:name`/`name/feature` references inside `[features]` tables, already handled). A real `cargo check --workspace` after *any* dependency removal is not optional, no matter how confident the grep-based check felt.
